# Legal + Security First: Agreed

The T3KDesigns one-pager, filled in for this project before release.

Project: **Agreed** (browser extension, formerly "PlainAgree")  Date: **29 October 2026**

## Legal

- [x] **What data do I collect?**
  Nothing is collected or sent anywhere. The extension reads, on the device: the consent banner's text and button
  labels, and a linked policy page on the same website. It stores one thing locally: "site + kind of card was
  closed", deleted after 7 days.
  *Changed for this checklist:* removed the per-site "policy drift" history (it was for a future feature, so not
  needed now), and stopped downloading policies from other websites.

- [x] **What am I promising? Can I prove it?**
  | Claim | Proof |
  |---|---|
  | "Free" | No payments, no server, no paid API. |
  | "Nothing about you is sent anywhere" | The only `fetch()` in the bundle is the same-website policy download, sent without cookies or a referrer. `test/policy-fetch.test.ts` checks that other sites are never contacted. |
  | "Reads the terms on your device" | The summarizer is plain code in `src/summarize/`; no network involved. |
  | Accuracy | **Not promised.** Green says "No red flags found" with the reason "That's not a guarantee." (it used to say "Looks fine"). |

- [x] **What if I'm wrong? Disclaimer where the user acts?**
  Every summary card shows "Automatic summary of the text on this page. Not legal advice." **above** the buttons,
  before the user decides anything (tested in `test/overlay.test.ts`). The popup repeats it. The privacy page explains
  what the colors do and don't mean.

- [x] **Terms / Privacy needed? Drafted, dated, linked where the user acts?**
  `extension/static/privacy.html` ("Privacy and disclaimer", dated 29 October 2026). It's bundled inside the extension,
  so the link always works offline and never points at a placeholder. It's linked from the toolbar popup and the demo
  site. The contact is real: GitHub Issues on the public repo.
  No separate Terms of Service: the extension is free, has no accounts and takes no actions, and the disclaimer
  covers the "what if it's wrong" risk. Revisit if that changes.

- [ ] **Whose stuff am I using?**
  - Shipped code is all ours: the bundles contain no third-party libraries. Dev tools (esbuild, TypeScript, Vitest,
    jsdom) are MIT/Apache-2.0 and not shipped.
  - Icons are generated by `scripts/make-icons.mjs`. Consent-manager names in `patterns.ts` are CSS selectors,
    used only to recognize their banners.
  - **Open:** the repo has **no license**, so by default nobody else may reuse the code. Pick one (or keep it
    all-rights-reserved on purpose) before inviting contributions.
  - **Open:** the name **"Agreed"** hasn't been checked for trademark conflicts or for existing store listings with the
    same name. Do a USPTO / store search before publishing.

- [x] **Who pays, who gets paid?** Nobody. Free, no in-app purchases, no ads, no affiliate links.

## Security

- [x] **Secrets in env / secret manager only.** There are no secrets: no backend, no API keys. Full git history scanned
  for API-key, token and private-key patterns on 29 October 2026: none found. (The removed Claude backend only ever
  had `sk-ant-REPLACE_ME` in an example file.)

- [x] **Least data, least permission.**
  Manifest permissions: **`storage` only**. *Changed for this checklist:* removed `host_permissions` for all websites
  and removed the background script; the policy download moved into the content script and is limited to the same
  website. The content script must run on http(s) pages to spot banners at all; that's the feature.

- [x] **No open endpoint that spends money.** There's no endpoint. *Changed earlier:* the Claude-backed `/summarize`
  Worker (the "open wallet") was removed in favor of on-device rules.

- [x] **Server checks, not just client.** No server, nothing to unlock or charge. Local storage only decides whether
  to re-show a card, and websites can't read or write extension storage.

- [x] **How would someone abuse this? Named abuses, blocked first:**
  1. **Auto-clicking consent the user didn't give.** *Blocked by removal:* "Accept for me" is gone. Agreed never
     presses anything on the page (tested: no "press it for me" offer exists).
  2. **A page plants reassuring text to get a green card** (for example, hidden "we don't sell your data" on a scam
     page). *Mitigated:* green never says "safe" ("No red flags found / That's not a guarantee"), every card says
     "Not legal advice", and the real terms are one tap away. Rules read only rendered banner text.
  3. **A page scripts the card** (fake clicks, reading it, restyling it). *Blocked:* closed Shadow DOM, and page CSS
     can't reach it.
  4. **Using Agreed to make requests to other servers.** *Blocked:* only same-origin policy URLs are fetched
     (tested), without cookies or a referrer.

- [x] **Failure must be safe.** If detection, the policy download or summarizing fails, the user gets the fallback
  card ("We couldn't read these terms right now. Nothing has been accepted.") or the banner text alone. The card is
  non-modal, never covers the page's own buttons by design, and closes with ×, Escape, or by itself when the banner
  goes away. A summary that recognizes nothing is yellow ("couldn't find the key details"), never a fake okay.

## Stop and get a real review if ANY of these apply

| Trigger | Applies? | Action |
|---|---|---|
| Money moves | No | — |
| Kids' data, or content made for kids | **Yes**: the target audience includes kids. No data is collected from anyone, but the card is content kids will read. | The privacy page tells children to ask a parent before agreeing to anything, and notes that many sites require age 13+. **Needs review** before marketing to kids. |
| Health, safety, or legal advice | **Partly**: the cards summarize legal terms. | Disclaimer on every card. **Needs review** of the rule wording (`src/summarize/rules.ts`) by someone qualified. |
| Other people's data at scale | No | — |
| Auto-action on the user's behalf | **Was yes, now no** | "Accept for me" removed. Re-adding any auto-action requires a review first. |

**Risks in plain language:**
- A child could read a reassuring card and agree to terms they aren't old enough to accept.
- A card could summarize a clause wrongly, or miss one, and someone could rely on it.
